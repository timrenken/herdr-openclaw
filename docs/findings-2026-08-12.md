# herdr 0.8.0 × OpenClaw 2026.7.1-2 实测记录（2026-08-12）

> 全部为实测，非推断。环境：macOS 26.5，herdr 0.8.0（Homebrew），
> openclaw 2026.7.1-2，Node 26.5。**易变，引用前先复核。**

## 一、herdr 的 agent 检测是 manifest 驱动的，但不能加新 agent ⚠️ 最重要

检测规则不在二进制里写死，而是数据驱动的 TOML：

```
远程缓存：~/.local/state/herdr/agent-detection/remote/<agent>.toml
本地覆盖：~/.config/herdr/agent-detection/<agent>.toml     ← 实测确认
CLI：herdr server agent-manifests / reload-agent-manifests / update-agent-manifests
```

本地覆盖**确实生效**：把 `hermes.toml` 复制到 `~/.config/herdr/agent-detection/`
并改高 version 后，`agent-manifests` 报 `source_kind: "local override"`、
`local_override_shadowing_remote: true`。

**但只对 herdr 已知的 agent 有效。** 放一个 `id = "openclaw"` 的 manifest 进去，
reload 后清单仍是 19 条、没有 openclaw，无任何报错——**被静默丢弃**。
二进制里有 `skipping unknown remote manifest agent` 这句话，对得上。

`herdr agent start --kind` 的取值是编译进 clap 的枚举，21 个：
`pi, claude, codex, gemini, cursor, devin, agy, cline, omp, mastracode, opencode,
copilot, kimi, kiro, droid, amp, grok, hermes, kilo, qodercli, maki`。

→ **结论：想让 herdr 认识一个新 agent，唯一的路是插件主动上报，不是写 manifest。**

## 二、`pane.report_agent` 接受任意 agent 名 ✅ 本项目成立的前提

```
herdr pane report-agent <PANE_ID> --source <ID> --agent <LABEL> --state <idle|working|blocked|unknown>
```

`--agent` 是自由字符串，没有枚举校验。实测把一个 pane 报成 `--agent openclaw` 后，
它出现在 `herdr agent list` 里，与真实的 claude / hermes agent 并列，
带 `agent_status`、参与侧栏与 herdroid 的 agent 视图。

配套：`report-agent-session`、`release-agent`、`clear-agent-authority`、`report-metadata`。

## 三、`report-metadata` 比想象的丰富

```
--display-agent <TEXT>        面板显示名（实测生效，agent get 里出现 display_agent）
--token <NAME=VALUE>          侧栏 token 位，可多个（实测生效，agent get 里出现 tokens{}）
--state-label <STATUS=TEXT>   给四态贴自定义文案
--ttl-ms <N>                  过期；watcher 死了以后陈旧数据会自己消失
--clear-token <NAME> / --clear-title / --clear-display-agent / --clear-state-labels
```

⚠️ **带 `--ttl-ms` 就必须自己续期。** herdr 到期即清，不会回退到上一次的值。
只在"值变了才重发"会让侧栏元数据一到 TTL 就永久消失（真机复现：15 秒后
`agent get` 的 `display_agent` 和 `tokens` 全变 `null`，而 watcher 明明还活着）。
本插件按半个 TTL 做心跳续期。

## 四、`agent_session` 写不进去（已知限制）❌

`pane report-agent-session --agent-session-id <ID>` 与
`pane report-agent --agent-session-id <ID>` 两条路都试过：**退出码 0、无报错，
但 `agent get` / `pane get` 的 `agent_session` 始终是 `null`**。短 id（`shortid123`）
和长 id（`tui-<uuid>`）都不行，排除了长度/字符集限制。

对照：herdr 自己起的 hermes agent 有
`agent_session: {agent:"hermes", kind:"id", source:"herdr:hermes", value:"20260812_132505_bb2b22"}`,
`source` 前缀是 `herdr:` —— 该字段很可能只对 herdr 自己启动并挂了 SessionStart 钩子的
agent 开放。

→ 本项目照常调用（契约上是对的，将来可能打通），但**不要依赖它做主键**。
OpenClaw 的会话 id 我们自己从状态行解析，存在 watcher 进程内。

## 五、OpenClaw TUI 的可观测面

进程识别（`pane process-info`）：

```json
{"argv0": "openclaw-tui", "name": "node"}
```

`openclaw tui` 会把 argv0 设成 `openclaw-tui`，这是最干净的识别信号；
同 pane 内还有两个 argv0 为 `openclaw` 的父进程。

底部两行（宽面板）：

```
 gateway connected | idle
 agent main | session tui-<uuid> | claude-cli/claude-opus-5 | think medium | tokens 144k/1.0m (14%)
```

**窄面板下会变形**，这是最容易漏的坑：

```
 connected | error                                    ← "gateway " 前缀被省掉
 agent main | session tui-<uuid> |                    ← info 行被 TUI 硬折
 claude-cli/claude-opus-5 | think high | tokens 144k/1.0m (14%)
```

折行**不是终端 wrap**：`pane read --source recent-unwrapped` 输出完全相同，
是 TUI 自己折的。解析器必须同时处理这两种形态（见 `test/detect.test.mjs` 的两份真机采样）。

多 agent 配置下 info 行还有第三种形态（实测你的 `her`）：

```
 agent side (side) | session tui-<uuid> | example-proxy/fast-model-v1 |
 think high | tokens ?/1.0m
```

两处新变化：**agent 名后带括号显示名**（`her (her)`），以及 **token 计数可以是 `?`**
（还没算出来）且此时没有百分比。前者会让 `agent\s+(\S+)\s*\|` 这种正则整条不匹配，
后果是 session/model/tokens 全丢——不是解析出错，是**静默丢字段**，最难发现。

### run 进行中：状态行换成结构相反的一行 ⚠️ 最容易漏

**空闲和忙碌用的是同一个槽位，但格式完全不同、顺序还是反的：**

```
空闲： gateway connected | idle
忙碌： ⠧ noodling… • 2s | gateway connected
```

只按空闲那种形态写正则，会导致**整个 run 期间一行都匹配不上**——表现就是
「结束时状态对，进行中不动」。dist 里的原始拼装（`updateBusyStatusMessage`）：

```js
if (activityStatus === "waiting") {
  // `${phrase}… • ${elapsed} | ${connectionStatus}`，phrase 来自 buildWaitingStatusMessage
  return;
}
setMessage(`${activityStatus} • ${elapsed} | ${connectionStatus}`);
```

外面套 `Loader` 的 spinner 前缀（braille，U+2800–U+28FF）。

三个必须注意的点：

1. **俏皮词不能当词表认。** `defaultWaitingPhrases` = flibbertigibbeting / kerfuffling /
   dillydallying / twiddling thumbs / noodling / bamboozling / moseying / hobnobbing /
   pondering / conjuring，但它是 `buildWaitingStatusMessage` 的**可配置入参**，
   而且有的带空格。只能按形状认：`… • <耗时> | <连接态>` 结尾。
2. **`elapsed` 会带空格。** `formatElapsed`：`<60s` 时是 `2s`，否则是 `1m 5s`。
   耗时段用 `\S+` 会截断。
3. **busy 行出现本身就等于 working**，因为它只在 `statusStartedAt` 有值（run 活跃）
   时渲染。不要试图从活动词推状态——waiting 那半永远查不到表。只有明确映射到
   blocked 的（`auth`）才升级。

### activityStatus 词表

`setActivityStatus()` 的调用点穷举（`dist/tui-*.js`）：

```
idle, sending, running, streaming, waiting, auth, error, disconnected, aborted
```

另有自由文案会走同一个字段，例如 `press ctrl+c again to exit`、`cleared input; ...`。
连接态词表：`connected, connecting, disconnected`。

映射见 `lib/detect.mjs` 的 `ACTIVITY_TO_HERDR`。

## 六、上报 `idle` 后 herdr 可能显示 `done`

`pane.report_agent` 只收四态（idle/working/blocked/unknown），但 herdr 对外的
`AgentStatus` 有五个值，多一个 `done`。实测：同一轮里两个都被上报为 `idle` 的 pane，
一个显示 `idle`、另一个显示 `done` —— 区别在于后者中途经历过 `working`。

即 `done` 是 herdr 自己从状态迁移推导出来的终态，不是我们能直接上报的。
另有一条同源实测：「终态是 done 不是 idle，`agent wait --until idle`
会等到超时」是同一件事。

→ **编排侧等 OpenClaw 跑完，要用 `--until done idle`，只写 idle 会挂。**
本插件不需要改任何东西，照常报 idle 即可。

## 七、通知：`notification.show` 自带用户配置，不必自建一套

```
herdr notification show <TITLE> [--body TEXT] [--sound none|done|request]
                                [--position top-left|top-right|bottom-left|bottom-right]
```

返回 `{shown, reason}`，reason ∈ `shown` / `disabled` / `rate_limited` /
`no_foreground_client` / `busy`。**这个枚举就是证据：投递方式、总开关、限流、
有没有前台客户端，herdr 侧已经按用户的 `[ui.toast]` 处理完了。** 插件重复读一遍
配置只会在两处各留一份会漂移的判断。

`[ui.toast]` 的键（herdr 文档）：`delivery`（herdr/terminal/system/off）、
`delay_seconds`、`position`，音效文件 `sound.path` / `done_path` / `request_path`；
另有 `[ui.sound.agents]` 按 agent 名配 `on`/`off`/`default`。

**蹭不上原生的自动通知**：原生 agent 的"需要注意"由 detection manifest 的
`visible_blocker` / `visible_idle` / `visible_working` 驱动（manifest 规则字段还有
`skip_state_update`），而 openclaw 没有 manifest（§1），`pane.report_agent` 也没有
对应参数。所以触发时机必须插件自己判断，只有发送这一步能复用。

## 八、`pane read --source` 有 `detection` 这一档

`visible | recent | recent-unwrapped | detection`。`detection` 就是 herdr 自己
喂检测规则的那一份快照，插件跟着用最贴近原生行为。

## 九、插件 agent 与原生 agent 的能力差异（逐条实测）

同一台机器上，拿一个插件上报的 openclaw pane 和原生 hermes/claude pane 对打：

| 能力 | 原生 | 插件 | 证据 |
|---|---|---|---|
| `agent list` / `get` | ✅ | ✅ | 字段级只差 `agent_session`；插件还多出 `display_agent`、`tokens` |
| `agent wait --until` | ✅ | ✅ | 参数是 `--timeout` 不是 `--timeout-ms` |
| `agent focus` / `rename` | ✅ | ✅ | rename 后 `name` 字段生效 |
| `agent prompt` | ✅ | ❌ | `agent_not_ready: not an active named agent` |
| `agent send-keys` | ✅ | ❌ | 同上 |
| `agent read` | ✅ | ❌ | **退出码 0 但返回空**；`pane read` 正常，两条是不同路径 |
| `agent explain` | ✅ | ❌ | `agent_explain_unavailable: does not have a detected agent label` |
| `agent start --kind` | ✅ | ❌ | 枚举编译在二进制里（§1） |
| `agent_session` | ✅ | ❌ | §4 |

"active named agent" 这个身份只有 `agent start` 能赋予，而 `--kind` 加不了 openclaw
—— 这是 `prompt` / `send-keys` 失败的同一个根。

herdr 内部明确区分**检测到的** agent label 与**上报的** agent label：
`agent explain` 只服务前者，报错原文就是 "does not have a detected agent label"。

### 按 agent 的配置项只接受已知 agent 名 ⚠️

用 `HERDR_CONFIG_PATH` 指向临时配置实测（不必动用户的文件）：

```
$ HERDR_CONFIG_PATH=/tmp/probe.toml herdr config check
config: issues found
unknown config key ui.sound.agents.openclaw; ignoring key
```

同一份配置里 `ui.sound.agents.hermes = "off"` **不报错** —— 所以那是已知 agent 的
枚举，不是开放 map。插件想复用它，功能上work（自己读文件即可），但会让用户的
`config check` 永久多一条警告。**插件的开关应该放插件配置目录**
（`herdr plugin config-dir <id>`，运行时经 `HERDR_PLUGIN_CONFIG_DIR` 注入）。

同理，侧栏按 agent 配色的名单也是固定的：
`pi / claude / codex / gemini / cursor / devin / agy / cline / open_code /
github_copilot / droid / amp / hermes`，openclaw 走默认色。

### 未验证

`resume_agents_on_restore`（herdr 重启后恢复 agent）没测 —— 要重启 server，
会杀掉所有面板。预期：pane 恢复但 openclaw 进程不会被拉起，watcher 发现前台
不再是 OpenClaw 就交还 authority。

## 十、沿用自另一个 herdr 插件项目的结论

以下几条来自同一作者早前写另一个 herdr 插件时的实测（herdr 0.7.5 时期），
本项目直接沿用、**未重新验证**。列在这里是为了说明代码里几个决定的由来：

- **错误信封走 stderr、结果走 stdout** → `lib/herdr.mjs` 两边都读
- **pane 侧是权威、agent 侧不是**：herdr 重启后 `agent list` 会留下幽灵记录
  （报 idle 且 interactive_ready，但同一个 pane_id 在 `pane read` 下是 `pane_not_found`）
  → `bin/startup.mjs` 开机先对账
- **`[[startup]]` 只需 `command`**，相对路径按 plugin_root 解析
- **命令一律 argv 数组、无 shell 展开**；运行时注入 `HERDR_PLUGIN_{ID,ROOT,CONFIG_DIR,STATE_DIR}`
- **`agent prompt` 不保证连回车一起提交**：某些 harness 的 TUI 上文字会停在输入框里，
  必须补发 enter 并靠状态变化确认——这是 `bin/prompt.mjs` 全部设计的由来
